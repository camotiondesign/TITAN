# Titan PMR — Light Social Post System

Reusable recipe for Titan PMR social/announcement posts in **light mode**, derived from the *Innovation Night — "Two systems. One workflow."* asset (`Innovation Night/`). Read this before making a new Titan PMR light post so the look stays consistent.

---

## Format
- **Canvas:** 1080 × 1350 (4:5). Other ratios on request (1080×1080 square alt is the common second crop).
- **Deliverable:** layered **SVG**, generated by script (never hand-edited). Two files per post:
  - `… -light-.svg` — **outlined** deliverable (all text → vector paths, no font dependency, plate embedded). This is what gets posted.
  - `… -light- -editable-.svg` — **master** (live `<text>`, Newake embedded as base64, SF Pro by name). Edit this for amends.
- 80px safe margin. Named groups + `inkscape:label` on every block; named slots for swappable art.

## Background plate
- Posts are a **type + logo layer composited over a supplied light-mode plate** (bright empty centre, product/UI objects bleeding from the corners, soft blue + orange washes).
- Plate is embedded as a downscaled JPEG (~1100px wide, q0.92) inside the SVG.
- If the plate ratio ≠ 4:5, cover-fill and **centre-crop** (objects read as corner-bleed). Prefer a native 4:5 plate when available; crop offset is tunable.
- **All type sits in the clear central band.** Nothing overlaps the objects or runs into the corner washes.

## Type rules
- **Fonts:** **Newake is the LOGO typeface ONLY** — use it solely for the `TITAN` wordmark (and other true logos). Everything else, including the headline, is **SF Pro** (Text Light / Medium / Bold).
- **Headline:** SF Pro **Bold, sentence case, solid black `#000000`**, set **heavier** via a matching stroke (`stroke-width ≈ 1.7`, `stroke-linejoin/​linecap round`, `paint-order:stroke`). Two short lines, centred. This is the hero, by a clear margin.
- **Gradient highlight:** use the **Titan PMR blue gradient `#2DA7FF → #2D40FF`** to pick out the key word(s) in the headline and/or descriptor (e.g. *workflow.*, *Partnership*). The gradient is the accent — use sparingly, on the words that carry the message. Everything else stays black/grey.
- **Hierarchy (top→bottom, all centred in the open middle):** eyebrow (small tracked caps) → headline (most space) → descriptor (light) → clear gap → contained detail chips → logo lockup near the bottom, above the safe margin and clear of any corner object.

## Contained chips (TitanUp-style, adapted to light)
- Dates/times and addresses sit in **rounded "pill" badges**, echoing the TitanUp contained-text pattern:
  - `rx = height/2`, fill `#FFFFFF` at ~0.78 opacity, hairline stroke `#0E1A2E` @ 0.10 opacity 1.2px, soft drop shadow (`dy 4, blur 9, #1B2A44 @ 0.16`).
  - One chip per piece (date/time chip slightly larger/darker than the address chip for hierarchy).
- No 📍 pin icon, no emoji.

## Logo lockup
- Partner logos in a single centred row, **matched optical size, evenly spaced**, separated by thin vertical hairline rules (`#C2CEDF`).
- `TITAN` is set in **Newake** (its real logotype). Partner names that lack supplied art are clean text placeholders in **named slots** (`logo-<name>`) — swap in real logo art when provided. **Never recolour supplied logos.**

## Light-mode palette
- Headline ink: solid black `#000000`
- Body / eyebrow: `#5A6678`
- Detail (date) text: `#2A3344`  ·  Address text: `#7C879A`
- Logo lockup ink: `#111111`  ·  Hairline rule: `#C2CEDF`
- Accent gradient (highlights only): `#2DA7FF → #2D40FF`
- The plate's washes provide the only large areas of colour.

## House rules (carry every time)
- British English. **No em dashes** (use "to", commas, full stops). No emoji on the graphic.
- Render bracketed placeholders literally (`[DATE TBC]` etc.); never invent facts.
- Newake demo font has **no period glyph** — in outline mode, fall back to SF Pro Bold for any missing glyph (already handled in the generator).

## Build pipeline (how to regenerate)
One `run_script`: load opentype.js → parse the 4 fonts (+ Newake base64) → downscale & embed the plate JPEG → `buildBody(mode)` rendering each text block as live `<text>` (master) or outlined `<path>` (deliverable), positioned by vertical centre with `dominant-baseline:central` / measured widths → save both SVGs. Keep named-group + named-slot structure intact.
